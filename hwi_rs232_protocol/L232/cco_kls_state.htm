CCO Relay State Reading Relay State via KLS / RKLS

 

Important supplemental information
This page is not part of the original Lutron L232 command reference. It documents observed processor behavior that the shipped documentation does not describe, and is included alongside the protocol docs because integrations depending on CCO state cannot be written correctly without it.

 

Summary
The command set provides no dedicated "request CCO relay state" command. There is no RCCO, and CCOCLOSE, CCOOPEN, and CCOPULSE are write-only. CCO relay state is nevertheless fully readable, because a CCO module reports its relay positions in the LED-state field of a KLS string. The relay state is therefore available both by unsolicited broadcast (with KLMON enabled) and by explicit query with RKLS.

This makes authoritative state reconciliation possible: an integration can issue RKLS at startup or after a reconnect and learn the true relay position of every CCO in the system, rather than assuming a default.

The CCOCLOSE page hints at the same shared mechanism from the other direction, noting that if a CCO command is sent to a normal keypad address "the command may temporarily change the state of the leds on that keypad." Relay position and LED state occupy the same underlying register.

Digit Mapping
Relay N appears at digit position 9 + N of the 24-digit LED-state field (digit position 1 being the leftmost). Relays 1 through 8 therefore occupy digit positions 10 through 17.

Digit Values
Within the relay window the digits do not carry the keypad LED meanings given in KLS_MON and RKLS. They are repurposed:

Digit Relay state Notes
1 Open (de-energized, device OFF) The resting value. Note this is not 0 - an idle relay reports 1, not Off.
2 Closed (energized, device ON) On a keypad this digit would mean Flash 1. On a CCO it means the relay is closed.
0 UNDOCUMENTED & UNDISCOVERED This digit has not been seen yet and meaning has not yet been discovered through reverse engineering.

LED Meaning for relay states
The LEDs indicate the position of the relays. When the LED is off, the common is connected to the normally closed terminal. When the LED is on, the common is connected to the normally open terminal.

Example 1 - CCO relay 1 at [01:05:03]
Relay 1 is digit position 10.

#Start, CCO relay 01:05:03(1) is off
LNET> RKLS,01:05:03
KLS, [01:05:03], 000000000111111110000000

#Relay 1 turned ON by keypad command (state then broadcast by HWI)
LNET>
KLS, [01:05:03], 000000000211111110000000

#Query again to confirm - the broadcast and the query agree
LNET> RKLS,01:05:03
KLS, [01:05:03], 000000000211111110000000

#Relay 1 turned OFF by keypad command
LNET>
KLS, [01:05:03], 000000000111111110000000

Example 2 - CCO relay 2 at [01:05:03]
Relay 2 is digit position 11. Only that digit moves; relay 1 stays open at 1.

#Start, CCO relay 01:05:03(2) is off
LNET> RKLS,01:05:03
KLS, [01:05:03], 000000000111111110000000

#Relay 2 turned ON by keypad (state then broadcast by HWI)
LNET>
KLS, [01:05:03], 000000000121111110000000

#Query again to confirm
LNET> RKLS,01:05:03
KLS, [01:05:03], 000000000121111110000000

#Relay 2 turned OFF by keypad command
LNET>
KLS, [01:05:03], 000000000111111110000000

Implementation Notes

1. The 9-digit offset should be treated as configurable, not as a constant. It is consistent across the CCO modules observed here, but it is undocumented by Lutron and may differ by module type, processor family, or firmware revision. Code that hard-codes it will break silently - reporting a neighbouring relay's position - rather than failing loudly.

2. Query at startup and after every reconnect. Unsolicited KLS broadcasts only tell you about changes that happen while you are listening. RKLS is the only way to establish the initial truth, and the only way to re-establish it after a dropped connection during which relays may have moved.

3. One RKLS per module address, not per relay. A single response carries all eight relay positions. Issuing one request per relay produces eight identical responses.
